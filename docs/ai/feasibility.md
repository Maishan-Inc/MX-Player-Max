# AI 后处理可行性评估

**诚实评估，不做乐观假设。**

## 能达到实时的场景

| 场景 | 分辨率 | 帧率 | 结论 |
|---|---|---|---|
| 超分 only | 1080p → 4K | 24fps | ✅ 中端独显/Apple Silicon。参考 Amazon IVS CNN 超分 8-9ms |
| 超分 only | 1080p → 4K | 60fps | ⚠️ 仅高端独显。9ms × 60 = 540ms/s > 16.7ms |
| 超分 only | 720p → 1440p | 30fps | ✅ 集显可达到低/中档 |
| 插帧 only | 1080p 24→60 | - | ✅ 好显卡上*大概率*可达到（参考 3-4ms/帧） |
| 插帧 only | 1080p 24→120 | - | ⚠️ 仅高端独显（6.7ms/帧远小于 8.3ms 预算） |
| 两者同时 | 1080p → ? | 24→60 | ❌ 见下 |

### ⚠️ 相乘成本：最关键的负面发现

**插帧 + 超分同时启用时，成本是相乘而非相加。**

以 1080p 24→60fps + ×2 超分到 4K 为例：

```
插帧：每帧合成 = 3ms（乐观估计）
超分：每帧 = 9ms（乐观估计）
总成本 = 3ms + 9ms = 12ms/帧
帧间间隔 = 1000/60 ≈ 16.7ms
```

看起来 12ms < 16.7ms，似乎可行。但 **这是理想情况：**

- 插帧到 60fps 意味着**超分每秒执行 60 次**而不是 24 次
- 插帧 2.5 倍后 GPU 负荷约 250% 基准
- 合成帧可能对超分模型来说更模糊（插帧伪影），增加超分难度
- 解码线程同时在新帧之间竞争 CPU 时间
- 浏览器渲染线程也需 1-2ms

**现实结论**：1080p 24→60fps + 4K 超分在旗舰显卡上**严格可能**，在高端以下**不可行**。默认配置在 4K 下不得同时启用两者。

## 达不到实时的场景

| 场景 | 结论 |
|---|---|
| 4K 下超分 + 插帧同时（除旗舰独显外） | ❌ 如上分析 |
| 集显 4K 超分（任何方式） | ❌ governor 强制关闭 |
| Fallback adapter（任何方式） | ❌ 探测器拒绝 AI |
| Firefox Linux（WebGPU 未进 stable） | ❌ 回退无 AI |
| Firefox Android（同上） | ❌ 回退无 AI |
| Safari iOS < 26 / Android 移动端 | ❌ 桌面优先，移动端未规划 |
| Real-ESRGAN（任何方式） | ❌ 比 Anime4K 慢约 1000 倍 |
| HTMLVideo 原生路径 + AI | ❌ 推迟至明确的时钟桥接设计后 |
| DRM 内容 + AI | ❌ 硬阻断（protected content 无法采样进 shader） |
| 全部 CPU 解码 + AI | ⚠️ 仅 240p→480p 超分 solo 才有可能 |

## 工作量估算

| 阶段 | 预估工作量 | 依赖 |
|---|---|---|
| 本次：契约层（文档 + 类型 + 骨架） | 1–2 周 | 无 |
| Phase C：超分 WGSL 实现 | 4–6 周 | 帧队列（阶段4）、WebGPU 渲染器（阶段6） |
| Phase D：Governor 实现 | 2 周 | 超分可用 |
| Phase E：插帧 WGSL 实现 | 6–10 周 | 超分 + Epoch 处理验证 |
| Phase F：加固（跨浏览器、设备丢失、压力） | 3–4 周 | 插帧 + 超分 |
| **合计（不含契约层）** | **15–22 周** | |

**一名有经验的图形/媒体工程师**：加上实现阶段 3/4/5/6 的时间（播放器能播视频），约 **6–9 个月** 后方可启动完整 AI 特性。

若只做超分（Phase C+D+A）：减 6–10 周，约 **10–14 周**（自阶段 6 完成后）。

|---|---|---|---|
| **RIFE 权重来源被下游封装污染** | 🟡 中 | 中 | RIFE 上游为 MIT，允许商用。风险在供应链：只从 `hzwer/Practical-RIFE` 按锁定 commit 取权重，绝不用第三方整合包（多为 CC BY-NC-SA） |
| **权重转换数值误差** | 🟡 中 | 高 | 建立数值等价性验证工装 |
| 相乘成本使旗舰演示无法达成 | 🟡 中 | 高 | **现在就设预期**：4K60 仅旗舰显卡，默认不开两者 |
| RT4KSR 无现成 WebGPU 移植 | 🟡 中 | 已确认 | 必须自行移植为 compute shader；工作量已计入 Phase C |
| `GridSample` WGSL 性能不达标 | 🟡 中 | 低 | 提前原型验证，不达标则砍插帧 |
| 用户已开 RTX VSR 造成重复处理 | 🟢 低 | 中 | 驱动级处理对网页透明，**无法程序化检测**；只能在 UI 提示 |

| 集显用户期待 AI 但无法使用 | 🟢 低 | 高 | 降级到 Anime4K low 档或 passthrough |
| ONNX Runtime 想升级导致依赖膨胀 | 🟢 低 | – | 已决定手写 WGSL，不引入 ORT |
