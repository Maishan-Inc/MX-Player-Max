# Performance evidence

`thresholds.json` is the versioned Phase 13 regression policy. Baseline JSON files are produced by
`pnpm quality:performance:collect` and validated by `pnpm quality:performance` after explicit review/promotion.

Every metric has a smoke and/or 30-minute policy threshold. A metric unavailable from browser APIs may
remain `null + reason` in smoke evidence, but a measured value is always checked. The 30-minute gate requires
measured first audio, A/V drift, CPU time, memory, and dropped-frame proxy values; nulls cannot close it.

The default collector runs a short Native smoke in installed Playwright Chromium and Firefox with and without
cross-origin isolation. It never installs a browser. Those records validate the collector only; they are not latest-two-stable evidence.
Run `pnpm quality:performance:collect -- --scenario=long-run-30m` for the full scenario. The collector hashes
the generated file itself and passes that digest into the browser report; a missing file or reused seed hash
fails before evidence is written. The media must now contain 1810 seconds, providing headroom for seek and EOF.

The 30-minute gate requires `tests/media/generated/long-run-vp8-opus-30m.webm`, generated by the command in
`tests/media/manifest.json`, followed by a complete `long-run-30m` collection. A shorter run cannot close
the drift or memory gate. Metrics unavailable from browser APIs stay `null` with a non-empty reason.

Offline example with Chromium only:

```sh
pnpm quality:performance:collect -- --browsers=chromium --backend=all
pnpm exec playwright test --project=performance-chromium --no-deps --workers=1
```

`--backend=native|custom|all` selects separate backend rows. `--browsers=chromium,firefox` requires both
executables to exist; a missing browser fails without downloading anything. Raw JSON, including run errors and
threshold failures, goes to `.release-tmp/performance/<timestamp>/` by default (`--output=<directory>` overrides
the location). Reports retain version/source hash, `validation.passed` and its failure reason. The collector does
not overwrite approved baselines. Only reviewed complete matrices belong in `baselines/`.

Startup observations separate probe/capability completion, subsequent backend readiness, subtitle setup and
play-to-first-frame latency. Subtitle loading runs alongside playback. Custom diagnostics include first PCM
observed consumption, worst absolute renderer submission drift, sample count, audio transport/underruns and sampled queue peaks.
PCM consumption is not first audible output, and submission drift is not physical A/V drift; those acceptance
metrics remain null until independently measured. Memory deltas may be negative when resources are released.

Duration counts sampled active, non-buffering playback, excluding pause/EOF tails. Memory samples are bounded,
and forward buffer is sampled only while actively playing. Native and Custom matrices cannot substitute for
one another. `pnpm release:readiness` requires all eight backend/browser/isolation long-run rows; schema checks
and a partial offline run cannot satisfy that release gate.
